# 携宠出行AI Agent 能力模块&分工架构
## 一、核心16大功能模块
### 1. 对话入口与任务识别
- 输出欢迎语
- 识别当前阶段（行前 / 行中）
- 识别当前任务类型（景点推荐、路线规划、医院推荐、证件提醒等）
- 进行任务分配
- 检查当前功能所需字段是否齐全
- 对缺失字段做最小追问

### 2. 用户画像 / 宠物画像 / 历史状态恢复
- 读取用户历史偏好
- 读取宠物画像（品种、年龄、体重、健康背景等）
- 读取既往病史
- 恢复行前已生成的景点/路线/酒店方案
- 恢复当前旅行状态和原始行程上下文

### 3. 规则、知识和经验信息检索
- 检索 AGENTS.md 里的父规则
- 检索航空 / 高铁 / 城市交通宠物规则
- 检索社媒经验库里的住宿、携宠出行、避坑知识
- 在规则引擎判定 PASS / FAIL 后，补充自然语言解释
- 把规则、政策和经验信息转成后续可执行约束

### 4.地址与地点标准化
用户输入多为模糊表达，如“去迪士尼周边”“我在酒店附近想找宠物医院”，Agent需统一标准化处理：
- 把目的地、酒店区域、当前位置转成标准经纬度 / 位置对象
- 对地点歧义做消歧
- 将后续 POI 检索、路线规划、医院推荐都绑定到统一位置基准上

### 5. 外部 API 调用与原始数据拉取
- 调天气 API 获取实时天气、分钟级天气、未来天气
- 调地图 API 获取地点、周边 POI、POI 详情
- 调路线 API 获取步行 / 驾车 / 公交距离与时间
- 调路线矩阵 API 计算多点之间的批量通勤时间
- 调实时交通 API 获取拥堵情况

### 6. 候选集合构建
- 候选景点集合
- 候选酒店集合
- 候选医院集合
- 候选宠物医院集合
- 候选替代景点 / 替代节点集合

### 7. 候选对象详情补全
- 名称、地址、类型
- 开放时间/营业时间
- 门票/价格
- 距离
- 联系方式
- 宠物友好标签
- 基础评价信息
- 服务能力或体验标签

### 8. 约束抽取与结构化建模
- 宠物约束：品种、年龄、体重、健康状态
- 用户约束：预算、偏好、体力、时间安排
- 交通约束：是否宠物友好、是否可达、通勤方式
- 天气约束：下雨、高温、短时天气恶化
- 时空约束：当前位置、目的地、每日游玩时长
- 经营约束：景点开放时间、医院营业状态
- 路线约束：返程时间、剩余游玩时间、节点顺序
- 合规约束：哪些交通方式默认禁止、哪些是硬限制

### 9. 过滤、打分与排序
- 过滤不适合宠物进入的景点
- 过滤超预算或时间不匹配的候选项
- 对景点做分类后排序
- 对宠物医院按距离与可达性排序
- 对医院按病情匹配度与到达效率排序
- 对替代景点按剩余时间、天气适配、原计划兼容性排序

### 10. 多点路线规划与行程序列优化
- 从多个景点里选出合理组合
- 安排景点访问顺序
- 计算单景点游玩时长
- 估计景点之间通勤时间
- 在天气、营业时间、预算、宠物限制下生成完整日程
- 输出 2–3 套差异化方案（高端 / 舒适 / 经济）
- 估算总花费与每日总时长

### 11. 住宿片区圈定与酒店组合
- 根据景点分布与通勤效率圈定核心住宿片区
- 在同一区位内找不同档次酒店
- 做酒店与路线的联合适配
- 输出“同区位酒店 + 多方案行程”的组合结果

### 12. 行中重规划
- 判断原路线哪里失效了
- 找出受影响节点
- 判断哪些节点需要替换
- 检索替代资源
- 重算当前位置之后的整段路线
- 生成新的后续行程方案
- 同时考虑实时天气、实时交通、剩余预算、剩余时长等因素

### 13. 行中局部替换
- 从当前位置出发召回附近替代景点
- 结合当前天气、剩余时间、宠物约束做过滤
- 保证新景点能尽量兼容原计划
- 输出替代景点推荐与替换理由

### 14. 应急场景下的紧急程度判断
- 根据用户主动上报症状判断紧急程度
- 根据宠物主动上报状态判断紧急程度
- 判断是「低 / 中 / 高 / emergency」四级
- 决定后续推荐逻辑是「最近优先」还是「能力匹配优先」

### 15. 医院 / 宠物医院推荐
- 检索附近医院 / 宠物医院
- 查医院详情
- 计算当前位置到医院的距离和 ETA
- 结合交通可达性筛选
- 输出 2–3 个候选机构
- 给出行动建议

### 16. 结果组织、解释与最终输出
- 把结构化结果转成自然语言
- 说明为什么推荐这些景点 / 医院 / 酒店
- 说明为什么某项规则不通过
- 说明替代路线和原路线的差异
- 对关键风险做提示
- 把最终结果写回 Memory，供后续继续使用
